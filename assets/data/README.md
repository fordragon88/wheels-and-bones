# Содержание игры «Колёса и Кости» — файлы данных

Здесь лежат тексты и шаги всех заданий, уроки Кабинета посадки, мануал Гильдии и справочники.
Их можно править в любом текстовом редакторе (Блокнот, VS Code) — программировать не нужно.
Код игры (`game.py`) только читает эти файлы при запуске.

## Что где лежит

| Файл | Что внутри |
|---|---|
| `jobs/index.json` | порядок заданий мастерской: `"jobs"` — обычные, `"folk"` — фольклорные (Баба Яга и др.; в игре появляются, только если на месте их картинки) |
| `jobs/<id>.json` | одно задание мастерской (`flat.json` — прокол Мартина, `caster.json` — Эльфийка и т. д.) |
| `tech/index.json`, `tech/<id>.json` | задания Гильдии Колёсников (уровень техника) |
| `seating/lessons.json` | 7 уроков Кабинета посадки |
| `seating/cases.json` | клиенты примерки (мерки тела, стартовые и верные настройки) |
| `seating/quiz.json` | вопросы зачёта (рисунок позы, вопрос, варианты ответа) |
| `seating/mentor.json` | реплики некроманта Мортимера |
| `manual.json` | страницы мануала Гильдии (на них ссылаются вопросы-спеки) |
| `manual_notes.json` | сноски из мануалов: задание → деталь → (мануал, страница, текст) |
| `tools.json`, `parts.json` | названия инструментов (с подсказкой) и деталей |
| `credits.json` | титры |

## Формат

Файлы в формате JSON (кодировка UTF-8). Главное:
- текст — в двойных кавычках `"…"`; кавычка внутри текста пишется как `\"`, лучше использовать «ёлочки»;
- между элементами — запятая, после последнего элемента запятой НЕТ;
- `true` / `false` — да / нет; `[ … ]` — список; `{ … }` — объект «поле: значение».

Поля `"source"` и `"comment"` есть у многих объектов, игра их не читает:
- `"source"` — **ссылки на страницы мануалов**, откуда взяты шаги и цифры (правило проекта: у каждого шага из
  мануала есть источник). Меняешь шаг по мануалу — поправь и ссылку. Не удалять!
- `"comment"` — заметки для разработчиков (откуда взялась формулировка, номер отзыва и т. п.).

## Задание мастерской (`jobs/<id>.json`)

`id` (совпадает с именем файла), `kind` (`manual` — ручная коляска, `power` — электро), `client`, картинки
`client_art`/`chair_art`, `chair_model`, `chair_name`, `title`, `symptom` (что рассказывает клиент), `parts`
(детали на коляске, включая отвлекающие), `inspect` (деталь → что видно при осмотре), `diagnosis` (варианты
диагноза), `steps` (шаги ремонта по порядку), `test` (проверка), `fact` (что игрок узнал), `thanks` (реплика клиента).
Если у задания несколько вариантов поломки — общий симптом, а `parts`, `inspect`, `diagnosis`, `steps`, `test`,
`fact`, `thanks` лежат в списке `variants`.

Диагноз: `{"text": "…", "correct": true}` или `{"text": "…", "correct": false, "feedback": "почему нет"}`.
Верный пишут первым — в игре варианты перемешиваются.

### Шаг ремонта

```json
{
  "comment": ["отзыв 108: прежняя формулировка была непонятной"],
  "instr": "Вставь монтажку между ободом и покрышкой, выведи борт через край обода и зацепи монтажку за спицу.",
  "tool": "lever",
  "part": "tire",
  "note": "Монтажки пластиковые — держи у конца, легко ломаются.",
  "ghost": "Барти: «Двумя ложками для обуви он это делал! ...или нет.»",
  "ghost_wrong": true,
  "wrongmsg": "Борт покрышки поддевают монтажкой — между ободом и покрышкой.",
  "alt": ["rim"]
}
```

| Поле | Обязательно | Что значит |
|---|---|---|
| `instr` | да | что сделать (текст шага над коляской; не длиннее 3 строк) |
| `tool` | да | нужный инструмент — ключ из `tools.json` (`hands`, `allen`, `pump` …) |
| `part` | да | деталь — ключ из `parts.json` (`tire`, `valve`, `brake` …) |
| `note` | | что игрок узнаёт после шага |
| `ghost` | | подсказка призрака Барти |
| `ghost_wrong` | | `true` — подсказка Барти здесь неверная (ловушка) |
| `wrongmsg` | | что сказать, если игрок ошибся на этом шаге |
| `alt` | | другие детали, которые тоже засчитываются (к шагам накачки ниппель `valve` игра добавляет сама) |
| `alt_tools` | | другие инструменты, которые тоже засчитываются |
| `mini` | | мини-игра вместо мгновенного действия: `pump` (накачать: `lo`–`hi` — зелёная зона, `mx` — предел шкалы, `unit`, `hint`), `gap` (зазор), `ping` (простучать спицы), `meter` (прочитать прибор: `prompt`, `reading`, `sub`, `options` — варианты `["текст", true/false, "пояснение"]`) |

Правила содержания (не больше 12 шагов в варианте, без трёх одинаковых ходов подряд, источники) — в `AGENTS.md`, §4.

## Задание Гильдии (`tech/<id>.json`)

Как обычное, плюс `track: "tech"`, `manual` (страницы из `manual.json`), `tools`, `intro`. Шаги — в свободном
порядке: `id` шага, `after` (какие шаги обязаны быть раньше), `safety: true` (техника безопасности — нарушение
проваливает задание), `failnote` (чем опасно), `spec` (вопрос по мануалу: `manual`, `prompt`, `options`).

## Как поправить текст и что запустить потом

1. Исправь текст в нужном файле и сохрани (UTF-8).
2. Проверь, что игра загружается: `python game.py --selftest` → `SELFTEST OK …`. Если в файле опечатка, игра сразу
   скажет, в каком файле и какое поле не так (например `jobs/flat.json: шаг 3: неизвестное поле "intsr"`).
3. Перевод на английский (если менялся русский текст): `python i18n_work/extract_new.py` — новые строки попадут в
   `i18n_work/_new_strings.json` → перевести по `i18n_work/GUIDE.md` в новый файл `i18n_work/en9_fixes99….json` →
   `python i18n_work/build_lang.py` (должно быть «строк с кириллицей на экране: 0»).
4. Пересобрать читаемую выгрузку квестов: `python docs/export_quests.py`.
5. «Золотой» эталон: `python art_tests/data_golden.py --check` сравнивает содержание с эталоном и после НАМЕРЕННОЙ
   правки, конечно, покажет отличие — это нормально. Убедись, что отличие только там, где ты правил, и обнови эталон:
   `python art_tests/data_golden.py --update`. При правках кода (не содержания) эталон обновлять нельзя — отличие там
   означает ошибку.
