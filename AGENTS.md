## 1. Что это за игра

Обучающий **симулятор ремонта инвалидных колясок** в уютном фэнтези-мире. Python + pygame, один основной файл
`game.py` (~11 тыс. строк), управление мышью и клавиатурой, русский язык + английский перевод.

- **Сюжет.** Мартин — добродушный зомби, вечно теряющий левую ногу. Взял коляску напрокат, она сломалась.
  Ему помогает призрак **Бартоломью (Барти)** — «видел, как делали мастера», подсказывает то дельно, то мимо
  (неверные подсказки — учебные ловушки). Мартин открывает мастерскую, чинит коляски фэнтези-клиентов, потом
  попадает в **Гильдию Колёсников** к **Мастерице Бренне** (призрак гномки-механика) и сдаёт экзамен на техника.
  Есть **Кабинет посадки** с **некромантом Мортимером** (учит позиционированию в коляске).
- **Жёсткие требования владельца:**
  - **Достоверность.** Шаги ремонта, цифры, коды ошибок — только из реальных мануалов производителей
    (база `D:\Project  BARC\manuals`, два пробела в имени). В заданиях есть комментарии `# source: файл pNN`.
    Игровые допущения помечаются `GAME`.
  - **Уважительный тон.** Юмор — от Мартина (нога), Барти, Мортимера, ситуаций. **Никогда** не над инвалидностью
    и не над пользователями колясок. Клиенты — уверенные, живые персонажи.
  - **Безопасность электрики.** Игра учит только безопасным пользовательским действиям; серьёзную электронику —
    «к сертифицированному технику».
- **Владелец** общается по-русски, работает итерациями «посмотрел → поправь», внимательно смотрит арт
  (замечает кривые колёса, висящие джойстики, лишние ручки). Любит, чтобы ему показывали варианты на выбор.

## 2. Как запускать

Репозиторий (приватный): https://github.com/fordragon88/wheels-and-bones (exe — в Releases).


```bash
python game.py                 # игра (Python 3.10 из PATH, pygame 2.6, numpy)
py game.py                     # двойной клик по .py -> Python 3.14 + pygame-ce (тоже должно работать)
python game.py --selftest      # главная проверка логики
python game.py --lang en       # английский;  --rs 1.5  — масштаб рендера;  --window — не во весь экран
python game.py --unlock        # всё открыто (предпросмотр);  --reset — сброс сохранения;  --mute — без звука
build_exe.bat                  # один файл dist\WheelsAndBones.exe (PyInstaller --onefile, ~64 МБ)
```

- `start_game.bat` — для двойного клика (держит консоль при ошибке).
- `build_exe.bat` обязан быть **ASCII + CRLF** (UTF-8/LF ломает cmd).
- exe хранит сохранения и настройки в `%APPDATA%\WheelsAndBones` (`save.json`, `settings.json`, `crash.log`).
  Из исходника — рядом с `game.py`.
- `crash.log` пишет faulthandler: при нативном падении там стек Python.

## 4. Устройство game.py (по разделам сверху вниз)

1. **Конфиг/палитра**: `WIDTH, HEIGHT = 1280, 720` (логические), `GUILD_REQ=5`, `INSPECT_REQ=2`, `EXAM_MAX_MISTAKES=3`,
   цвета `AMBER, CYAN, GOOD, BAD, GHOST, PURPLE, WHITE, GREY, DIM, PANEL, PANEL2`. `DATA_DIR`, `SAVE_PATH`, `SETTINGS_PATH`.
2. **Слой рендера в разрешении экрана** (см. §7 — очень важно).
3. **Шрифты/текст**: `font(size,bold)` → `LFont`; `draw_text`, `fit_text` (ужимает/обрезает), `wrap_lines`, `draw_wrapped`.
4. **Язык**: `tr()` переводит на выводе; `set_lang`, `system_lang`, словарь `assets/lang_en.json`; шаблоны `{0}`.
5. **Анимация** (без состояния, от времени): `ease_out/ease_back/appear`, `add_glow`, `blit_idle`, `draw_ambient`, конфетти.
6. **Ассеты**: `load_image(name, size)` (PNG в пикселях экрана, иначе `VECTOR_ART`, иначе заглушка), `tool_icon`.
7. **Визуализация действий**: анимация инструментов, тест-драйв, шутки про ногу Мартина (`LEG_GAGS`).
8. **Звук**: синтезатор эффектов (`snd(name)`), петли атмосферы (`set_ambient`), музыка `music_update/music_theme`,
   громкость `VOL` (master/music/sfx/amb/on). `M` — выкл/вкл звук.
9. **Векторный арт** `VECTOR_ART` — запасной рисунок кодом, если PNG нет.
10. **3D**: `Mesh3D`, `project_mesh` (+ numpy-путь `_project_mesh_np`), процедурные запасные модели,
    `get_ai_chair3d(chair_art, lod=False)` грузит `assets/models`. `AI_MODELS` — список колясок с моделями.
11. **Данные**: `TOOLS`, `PARTS`, `MANUAL` (спеки Гильдии), `SEAT_*` (кабинет посадки), `JOBS`, блок «Вторая волна»
    (`JOBS += [...]`, `PARTS.update`, `MANUAL.update`), `TECH_JOBS`, `ALL_JOBS`. Хелперы: `S(...)` шаг, `D(...)` вариант
    диагноза, `T(...)` шаг Гильдии, `resolve_job` (варианты поломки).
12. **`class Game`**: сцены `title, intro, hub, job (diagnose → repair → test), result, garage, guild, exam_result, failed,
    seating, ending`. Методы `draw_<сцена>`, `click_<сцена>`, `handle_event`, `update`. Оверлеи: 3D-осмотр (`v3d`),
    3D в окне диагностики (`m3d`), мануал, мини-игры (`mini_pending`), панель звука.
13. **`run_selftest()`** и **`main()`**.

### Где что лежит (для людей)
- Тексты квестов, диагнозы, шаги и решения — всё в `game.py` (`JOBS`, `TECH_JOBS`, `SEAT_*`, `CLIENT_TALK`, `MANUAL`);
  английский — `assets/lang_en.json` (собирается из `i18n_work/en*.json`). Читаемая выгрузка — `docs/QUESTS*.md`
  (пересобирать `python docs/export_quests.py` после правок квестов).
- Сохранения: из исходников — рядом с game.py (save.json, settings.json, feedback.json, crash.log); exe —
  `%APPDATA%\WheelsAndBones\`; браузер — localStorage (`wnb:save.json` …).
- Инструмент `eyes` («Глаза») — для визуальных шагов; `hands` — потрогать, нажать, снять/поставить, работать джойстиком.
- Деталь `controller` = пульт с джойстиком (весь блок); `joystick` = только ручка. «Контроллер» в текстах — электроника.

## 6. Интерфейс и управление
- Главный экран: карточки 4×2 с крупной коляской, листание ◀ ▶.
- Задание: коляска по центру; в диагнозе — живая 3D-модель (тянуть мышью — вращать, колесо — зум, ПКМ — сброс),
  кружки деталей; список деталей и диагнозы — справа. **V** или кнопка «ОСМОТР 3D» — большой 3D-осмотр
  (R / ПКМ — сброс вида, +/− — зум, Esc/Tab — закрыть). В ремонте — арт + хотспоты + панель инструментов.
  (Раньше 3D открывался по Tab — теперь Tab двигает фокус клавиатуры.)

### 6б. Доступность: вся игра с клавиатуры + озвучка (для незрячих и слабовидящих)
- **Клавиши:** стрелки — пункт (← → двигают ползунки), Tab/Shift+Tab — группа, Enter/Пробел — нажать, Esc — назад,
  R — повторить «где я и что делать», T — прочитать весь экран, H — подсказка призрака, C — реплика клиента,
  F1 — справка, F2 — озвучка вкл/выкл. Рамка фокуса видна, пока работаешь с клавиатуры.
- **Как устроено:** каждый кадр `CAPTURE` записывает тексты (`draw_text`/`draw_wrapped`/`fit_text`) и кнопки
  (`Button.draw`) — только на главном кадре. `a11y_items()` = особые пункты (детали, инструменты, диагнозы,
  операции, спицы, шкалы, ползунки посадки/громкости, страницы мануала…) + все нарисованные кнопки (подпись —
  label/sub, у пустой кнопки — текст внутри неё, у короткой — подпись строки слева). Модальные окна вызывают
  `_cap_modal()` в начале отрисовки — тогда доступно только окно. Нажатие = `act()` или синтетический клик в центр.
  **Новая кнопка через `Button` доступна с клавиатуры автоматически**; новый кликабельный элемент без `Button`
  нужно добавить в `a11y_items()`, новый оверлей — начать с `_cap_modal()`.
- **Озвучка:** `SPEECH` (класс `Speech`): если запущен экранный чтец (NVDA, JAWS…) — через Tolk (`cytolk`), его
  голосом и брайлем; иначе голос Windows (SAPI через pywin32) на языке игры. Всё за кадр — одной фразой
  (`self.say()` → очередь → `a11y_frame()`). Автоматически звучат: описание экрана при смене (`a11y_summary`),
  тосты (`flash`), реплики клиентов/Барти (если «Реплики героев вслух»), значение насоса (+ тон `snd_pitch`).
  Включается сама, если Windows сообщает о работающем чтеце (`screen_reader_running`), или F2 / `--speak`.
- **Настройки → ДОСТУПНОСТЬ** (`A11Y` в settings.json): озвучка, реплики вслух, скорость голоса Windows,
  контрастный фон (тёмный фон без частиц), «текст сразу» (без печати по буквам).
- У вопросов зачёта по посадке есть `desc` — словесное описание рисунка для озвучки.
- Проверка: `python art_tests/keyboard_playthrough.py [en]` — «незрячий игрок» проходит все задания, Гильдию,
  примерку и настройки одними клавишами (в en — ловит кириллицу в озвучке). Короткая версия — в селфтесте.
- Esc — назад (двойной Esc в задании — выйти), **F11 / Alt+Enter** — полный экран, M — звук, RU/EN — справа вверху.

## 7. Рендер в разрешении экрана (читай перед правками графики!)
Вся раскладка в **логических** координатах 1280×720, пиксели — ×`RS` (выбранное разрешение / 720; в режиме АВТО — высота области игры / 720, не больше 2).
- Создавай поверхности через **`Surf(size, flags)`**, а не `pygame.Surface`. Рисуй через **`DR.*`** (обёртка `pygame.draw`),
  `aa_rect`/`aa_circle` (сглаженные), масштаб — **`TF.smoothscale/rotozoom`**, мышь — **`mouse_pos()`**.
  Имена `D`, `T`, `S` **заняты** конструкторами заданий — не используй их для другого.
- В `main()` события мыши делятся на RS, кадр рисуется в `Surf((1280,720))`, потом выводится на экран.
- 3D рисует сырым `pygame.draw` с `ss * RS` (полигоны уже в пикселях).
- Тесты/селфтест идут при RS=1; для проверки высокого разрешения — `python art_tests/rs_smoke.py 2`.

## 11. Грабли (не наступать повторно)
- Анимации, которые режут/растягивают спрайт, считать в РЕАЛЬНЫХ пикселях (`pygame.Surface.*`, RS), а не в
  логических: округление логических координат даёт щели и «рваные» строки на RS 1.5.
- Файлы перевода сливаются в порядке имени (`en1` < `en10…` < `en2`): исправления класть в файл, который сортируется
  ПОСЛЕ исправляемого (например `en9_fixes.json`), иначе правка перезапишется.
- Короткие ключи словаря (`на`, `из`) опасны: склейка подставляет их в любые непереведённые строки — для
  озвучки язык выбирается в коде (`_of`, `speech_clean`).
- Браузер (pygbag): `import pygame` должен быть в main.py; окно создавать сразу в async-функции main.py;
  `import numpy` ломает дисплей («video driver did not add any displays»); на localhost шаблон ищет пакеты на
  локальном сервере — проверять через http://127.0.0.1:8000; вкладка в фоне не грузится.
- Синтезированные звуки (`_to_sound`) — сырые байты: формат обязан совпадать с `pygame.mixer.get_init()`.
- `typed()` при «тексте сразу» (`A11Y["instant"]`) всё равно записывает `_typing[key]` — `draw_intro` читает `_typing["intro"]` напрямую (падение, найдено monkey-тестом). monkey_test всегда выходит с кодом 0 — смотри строку «уникальных падений».
- Смена разрешения/режима — только через `apply_display()` / `toggle_fullscreen()`; кадр — `DISPLAY["frame"]` (пересоздаётся
  в `_update_rs`), вывод — `present()`. Новые модульные кэши с картинками добавлять в сброс внутри `_update_rs`.
  Координаты мыши из событий/`pygame.mouse` переводить только через `window_to_logical` / `mouse_pos()`.
- В данных заданий верный вариант стоит первым, но на экране порядок случайный. В тестах и ботах искать верный ответ
  по флагу (`correct` / `o[1]`), никогда по индексу 0.
- **Шрифт только из `assets/fonts/`.** Не возвращать `SysFont` как основной: на чужих компьютерах нет DejaVu, и значки
  (⚑ ◉ ✔ ★ ⟲ ▶) превращаются в квадратики. Новые значки проверять, что они есть в DejaVu Sans.
- **GPU-рендер** (`gl_render`, блок «GPU-рендер 3D» в game.py): не менять формулу проекции в шейдере отдельно от
  `project_point`/`project_mesh` — иначе кружки деталей и клики разъедутся с картинкой. Картинка GL уже в пикселях
  экрана — накладывать через `pygame.Surface.blit(..., bbox)`, без `Surf.adopt` (дорого при ×2).
- `LFont.render` отдаёт надпись из кэша без копии: `set_alpha` ставить только прямо перед `blit`.
- **Порча памяти в слое Surf.** `Surf.adopt/copy/subsurface` должны создавать копию **сразу точного размера**
  (`Surf(logical, flags, real=(w, h))`). Никакого `smoothscale` свежей копии на ±1 px — access violation.
- **Окно SDL.** Не использовать `Window.from_display_module()` / `pygame._sdl2` без хранения ссылки — был краш (объект
  умирал, SDL обращался к освобождённой памяти). Сейчас окно управляется только через `pygame.display.set_mode`.
- Не называть свои функции/классы `D`, `T`, `S` (это хелперы заданий).
- `build_exe.bat` — только ASCII + CRLF.
- numpy нужен для 3D (без него — запасной арт); exe собирать с numpy.
- Не удалять `settings.json`/сохранения владельца при тестах. Перед большими правками `game.py` — бэкап
  `art_tests/game.py.bak_before_<что>`.
- Qwen иногда копирует образец стиля вместо задания — смотреть все варианты.
- YuE2 (музыка) почти всегда поёт; для инструменталок нужен другой генератор.
- Новые детали: добавить в `PARTS`, разметить на 3D-модели (part-лейбл граней в билдере), поставить хотспот на арте —
  селфтест проверяет всё это.
