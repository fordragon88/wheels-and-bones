# Перенос «Колёс и Костей» на Godot — план

Ветка `godot-port`, папка `godot/` (проект Godot 4.7.2, редактор — `D:\Godot\Godot_v4.7.2-stable_win64.exe`).
Релиз игры остаётся на pygame (`game.py`) до тех пор, пока перенос не догонит его по содержанию и доступности.
Этот файл — рабочий план и состояние переноса; обновлять вместе с работой.

## Зачем
Цель владельца (10.11.2026): удобно играть с телефона, планшета и из браузера. В pygame/pygbag упёрлись в скорость
(12–14 кадров/с на телефоне — Python рисует ~230 картинок за кадр), долгую загрузку (интерпретатор Python в браузере,
14,5 МБ + разогрев) и отсутствие настоящих приложений для Android/iOS. Godot даёт отрисовку на видеокарте, родной
экспорт в браузер (WebAssembly без Python), Android/iOS/Windows из одного проекта, готовую систему интерфейса с
фокусом для клавиатуры/геймпада и поддержку программ чтения с экрана (с Godot 4.5).

## Принципы
1. **Содержание — одно на обе версии.** Задания, Гильдия, посадка, мануал, инструменты, детали, титры живут в
   `assets/data/**/*.json` (вынесено 10.11 как раз для этого). Godot читает те же файлы; правка содержания делается в
   одном месте. В проект они попадают копированием (`godot/tools/sync_content.py`), вручную в `godot/content/` не править.
2. **Перенос срезами, а не «всё сразу».** Каждый шаг — играбельный кусок, который можно запустить и показать.
3. **Сначала как есть, потом лучше.** Внешний вид и правила — как в релизе (тот же холст 1280×720, те же картинки,
   тексты, цвета). Улучшения, которые даёт движок (настоящая 3D-коляска вместо кадров поворота, телефонная раскладка),
   — отдельными шагами после паритета.
4. **Доступность — не «потом».** Клавиатура, геймпад, одна кнопка, озвучка, размер текста, «Без анимации», шрифт для
   лёгкого чтения закладываются в каркас с первого экрана и проверяются на каждом срезе.
5. **Проверки с первого дня.** Самопроверка без окна (`godot --headless`), снимки экранов для сверки с pygame-версией,
   позже — боты прохождения (как `ui_playthrough.py`).

## Что переносится без переделки
| Что | Откуда | Как попадает в Godot |
|---|---|---|
| Содержание (задания, шаги, тексты, источники) | `assets/data/**/*.json` | копия в `content/data/`, читает `Content` |
| Перевод на английский | `assets/lang_en.json` (русская строка → английская) | копия, словарь в `Loc` |
| Портреты, коляски, фоны, инструменты | `assets/*.png` | копия в `content/img/`, обычный импорт |
| Кадры поворота колясок (36 на коляску) | `assets/turntable/*.jpg + *.a.png` | склейка в WebP с прозрачностью, `content/frames/turntable/` |
| Петли анимаций (машут, проезд, волшебство) | `assets/anim/*/NN.jpg + NN.a.png` | то же, `content/frames/anim/` |
| Координаты кружков деталей | `assets/turntable/index*.json` | копия; проекция — порт `project_point` |
| Звуки (в pygame синтезируются кодом) | `game.build_sounds()` | один раз выгружаются в WAV, `content/sfx/` |
| Музыка, шрифты | `assets/music`, `assets/fonts` | копия |
| Сохранение | `save.json` (тот же набор ключей) | `user://save.json`; коды прогресса совместимы |

Кадры (`content/frames/`) **не импортируются** редактором (в папке `.gdignore`): их ~3800, импорт занял бы минуты и
раздул бы проект. Игра читает WebP сама (`Frames`), по мере надобности и с выгрузкой — так же, как сейчас в браузере
петли качаются по герою. В браузерном экспорте эти файлы будут лежать рядом с игрой и подгружаться по сети.

## Что пишется заново (GDScript)
Весь код игры: экраны, логика задания, мини-игры шагов, рисованный скелет в Кабинете посадки, ввод, доступность,
ссылки-задания и коды, отправка замечаний. В `game.py` это ~16,5 тыс. строк; переносится по экранам.

Принцип экранов: один `.tscn` на экран (корень Control + скрипт `extends Screen`), содержимое собирается кодом в
`build()`; состояние — в переменных экрана, поэтому смена языка/размера текста/шрифта просто пересобирает экран
(`rebuild()`, фокус возвращается на элемент с тем же именем). Всё нажимаемое — настоящие `Button` (фокус с
клавиатуры/геймпада, Enter/пробел, `accessibility_name` для чтеца экрана); неинтерактивное рисуется в `_draw()`
теми же размерами и цветами, что в game.py (`UI.draw_text(pos — левый верх / центр / правый верх)`,
`UI.wrap_lines` — тот же перенос по словам, размеры шрифта × TEXT_K). Рамка фокуса видна только после клавиатуры
или геймпада (`UI.kb_active`, как kb["active"] в pygame).

Кадры поворота (Frames + ChairView): `Frames.want_turntable(art)` ставит 36 WebP в очередь (с кадра текущего
ракурса в обе стороны) и выгружает прошлую коляску; декодирование `Image.load_webp_from_buffer` + mipmaps — в
`WorkerThreadPool` (до 3 кадров), без потоков — по ~6 мс за кадр игры; `ImageTexture` создаётся в главном потоке.
Пока кадров нет — рисунок коляски (`art_matched`). Рисование и кружки — прямой порт `_draw_turntable`,
`_m3d_frame`, `_m3d_spots`, `project_point`: кадр `index = round((yaw − yaw0)/(2π/n)) mod n`, масштаб
`fr.h/1250·zoom`, кадр в `(ax + off·scale, ay + off·scale)` размером `px·scale/ref`, тень — четырёхугольник под
колёсами в 1/10 разрешения, растянутый (размытие). Центры деталей — `centers` + `PART_CENTER_FIX` (из game.py в
game_consts.json); ближняя к низу экрана точка детали, скопления — веером, раздвигание, выноска к детали —
попиксельно совпадает с pygame (сверено на flat и joystick). Петли героев — `Frames.loop_frame(name, t)`:
показываются, когда все кадры в памяти (до того — статичная картинка), не показанные 30 с выгружаются.
Автозагрузки (синглтоны):
- `Content` — задания/варианты/Гильдия/посадка/инструменты/детали из JSON; проверка целостности при старте.
- `Loc` — `Loc.t("русская строка")` → строка на текущем языке (как `tr()` в игре); язык RU/EN.
- `Settings` — громкости, язык, размер текста, «Без анимации», шрифт, одна кнопка, качество; `user://settings.json`.
- `SaveGame` — прогресс в формате `save.json`; резервная копия; коды прогресса/заданий (позже).
- `Audio` — звуки по имени (`Audio.sfx("ok")`), музыка сцен с плавной сменой.
- `Frames` — кадры поворота и петли: загрузка WebP в фоне, кэш, выгрузка.
- `Nav` — смена экранов с переходом, стек «назад», параметры запуска (`?jobs=…` в браузере — позже).
- `Speech` — озвучка для незрячих (встроенная поддержка Godot + свои объявления).

## Риски
- **Озвучка в браузере.** Встроенная поддержка чтения с экрана в Godot работает на компьютере; в браузерном экспорте
  холст для неё «чёрный ящик». Возможно, придётся дублировать объявления в скрытую область страницы, как сейчас.
- **Память на телефоне.** Кадры без сжатия в видеопамяти: 36 кадров коляски ≈ 50 МБ. Держать только текущую коляску
  и текущую петлю, грузить заранее по одному кадру.
- **Размер браузерной сборки.** Движок ≈ 10 МБ в сжатом виде до первого кадра игры; всё тяжёлое — вне основного пакета.
- **Объём.** Кабинет посадки и доступность — самые дорогие части; оценка всего переноса — недели работы срезами.

## Отличия от релиза сейчас (сверка по снимкам tests/ref ↔ tests/shots, средняя разница 2,5–5,5 из 255)
- Буквы местами сдвинуты на 1 px (кернинг/хинтинг Godot против SDL_ttf), жирный — заметнее; раскладка та же.
- Пылинки, парение Барти, печать по буквам, порядок диагнозов (перемешивание) — от времени/случая, не попиксельно.
- Нет атмосферных петель звука (amb: pygame синтезирует их кодом, в WAV не выгружены) — только эффекты и музыка.
- «Без анимации» по системной настройке Windows/браузера не включается само (в pygame — SPI/prefers-reduced-motion).
- Нет «волшебства» на портрете, окна сносок мануала, 3D-осмотра (V), вступления (титул без прогресса ведёт сразу в
  мастерскую, где до обучения только Мартин), справки F1, озвучки F2.
- Улика осмотра — сообщением сверху (как в релизе: flash), а не в пузыре Барти.

  папок с `.gdignore` (если нет — снимать `.gdignore` перед экспортом скриптом или класть кадры рядом с игрой и

  `Frames` для этого надо научить качать (сейчас только файлы). Экспорт однопоточный — `Frames` сам переходит на
  загрузку «по кадру за кадр игры» (`OS.has_feature("threads")`).
- `content/data/*.json`, `i18n/*.json` — ресурсы JSON, попадают в экспорт как есть; звуки и музыка — импорт.

## Грабли Godot 4.7 (найдено при переносе)
- Живые области чтеца экрана: `AccessibilityServer.AccessibilityLiveMode.LIVE_POLITE` (не `DisplayServer.…`).
- Скрипт `-s res://…` компилируется ДО того, как появляются имена автозагрузок: «Identifier not found: Settings».
  Поэтому `tests/selftest.gd` только запускает `tests/selftest_runner.gd` (тот компилируется позже).
- `set_anchors_preset(FULL_RECT)` + `size = …` даёт двойной размер (смещение правого края прибавляется к якорю 1,0):
  только `set_anchors_and_offsets_preset`.
- `rendering/textures/canvas_textures/default_texture_filter`: 0 Nearest, 1 Linear, **2 Linear Mipmap**, 3 Nearest
  Mipmap (с 3 тень коляски была «лесенкой»). Своим `ImageTexture` (кадры) — `Image.generate_mipmaps()`.
- `Viewport.push_input(e)` без окна (headless) пересчитывает координаты под крошечное окно — клики мимо;
  `push_input(e, true)` — координаты холста.
- Задачи `WorkerThreadPool` надо дождаться до выхода (`Frames.wait_tasks()`), иначе поток пишет в удалённый узел.
- Высота строки DejaVu: `font.get_height()` Godot на 1 px больше, чем у pygame (SDL_ttf: ceil(2384/2048 × px)) —
  `UI.px_height()`; иначе раскладка экрана задания съезжает на 2 px.
- Скрытая кнопка не получает фокус при входе: «начать» на титуле берёт фокус, когда появляется.
- `_draw()` без окна вызывается (рендер-заглушка) — самопроверка перевода видит всё, что рисуют экраны.
