# Перенос «Колёс и Костей» на Godot — план

Ветка `godot-port`, папка `godot/` (проект Godot 4.7.2, редактор — `D:\Godot\Godot_v4.7.2-stable_win64.exe`).
Релиз игры остаётся на pygame (`game.py`) до тех пор, пока перенос не догонит его по содержанию и доступности.
Этот файл — рабочий план и состояние переноса; обновлять вместе с работой.

## Зачем
Цель владельца (10.11.2026): удобно играть с телефона, планшета и из браузера. В pygame/pygbag упёрлись в скорость
(12–14 кадров/с на телефоне — Python рисует ~230 картинок за кадр), долгую загрузку (интерпретатор Python в браузере,
14,5 МБ + разогрев) и отсутствие настоящих приложений для Android/iOS. Godot даёт отрисовку на видеокарте, родной
экспорт в браузер (WebAssembly без Python), Android/iOS/Windows из одного проекта, готовую систему интерфейса с
фокусом для клавиатуры/геймпада и поддержку программ чтения с экрана (с Godot 4.5).

## Принципы
1. **Содержание — одно на обе версии.** Задания, Гильдия, посадка, мануал, инструменты, детали, титры живут в
   `assets/data/**/*.json` (вынесено 10.11 как раз для этого). Godot читает те же файлы; правка содержания делается в
   одном месте. В проект они попадают копированием (`godot/tools/sync_content.py`), вручную в `godot/content/` не править.
2. **Перенос срезами, а не «всё сразу».** Каждый шаг — играбельный кусок, который можно запустить и показать.
3. **Сначала как есть, потом лучше.** Внешний вид и правила — как в релизе (тот же холст 1280×720, те же картинки,
   тексты, цвета). Улучшения, которые даёт движок (настоящая 3D-коляска вместо кадров поворота, телефонная раскладка),
   — отдельными шагами после паритета.
4. **Доступность — не «потом».** Клавиатура, геймпад, одна кнопка, озвучка, размер текста, «Без анимации», шрифт для
   лёгкого чтения закладываются в каркас с первого экрана и проверяются на каждом срезе.
5. **Проверки с первого дня.** Самопроверка без окна (`godot --headless`), снимки экранов для сверки с pygame-версией,
   позже — боты прохождения (как `ui_playthrough.py`).

## Что переносится без переделки
| Что | Откуда | Как попадает в Godot |
|---|---|---|
| Содержание (задания, шаги, тексты, источники) | `assets/data/**/*.json` | копия в `content/data/`, читает `Content` |
| Перевод на английский | `assets/lang_en.json` (русская строка → английская) | копия, словарь в `Loc` |
| Портреты, коляски, фоны, инструменты | `assets/*.png` | копия в `content/img/`, обычный импорт |
| Кадры поворота колясок (36 на коляску) | `assets/turntable/*.jpg + *.a.png` | склейка в WebP с прозрачностью, `content/frames/turntable/` |
| Петли анимаций (машут, проезд, волшебство) | `assets/anim/*/NN.jpg + NN.a.png` | то же, `content/frames/anim/` |
| Координаты кружков деталей | `assets/turntable/index*.json` | копия; проекция — порт `project_point` |
| Звуки (в pygame синтезируются кодом) | `game.build_sounds()` | один раз выгружаются в WAV, `content/sfx/` |
| Музыка, шрифты | `assets/music`, `assets/fonts` | копия |
| Сохранение | `save.json` (тот же набор ключей) | `user://save.json`; коды прогресса совместимы |

Кадры (`content/frames/`) **не импортируются** редактором (в папке `.gdignore`): их ~3800, импорт занял бы минуты и
раздул бы проект. Игра читает WebP сама (`Frames`), по мере надобности и с выгрузкой — так же, как сейчас в браузере
петли качаются по герою. В браузерном экспорте эти файлы будут лежать рядом с игрой и подгружаться по сети.

## Что пишется заново (GDScript)
Весь код игры: экраны, логика задания, мини-игры шагов, рисованный скелет в Кабинете посадки, ввод, доступность,
ссылки-задания и коды, отправка замечаний. В `game.py` это ~16,5 тыс. строк; переносится по экранам.

Принцип экранов: один `.tscn` на экран (корень Control + скрипт `extends Screen`), содержимое собирается кодом в
`build()`; состояние — в переменных экрана, поэтому смена языка/размера текста/шрифта просто пересобирает экран
(`rebuild()`, фокус возвращается на элемент с тем же именем). Всё нажимаемое — настоящие `Button` (фокус с
клавиатуры/геймпада, Enter/пробел, `accessibility_name` для чтеца экрана); неинтерактивное рисуется в `_draw()`
теми же размерами и цветами, что в game.py (`UI.draw_text(pos — левый верх / центр / правый верх)`,
`UI.wrap_lines` — тот же перенос по словам, размеры шрифта × TEXT_K). Рамка фокуса видна только после клавиатуры
или геймпада (`UI.kb_active`, как kb["active"] в pygame).

Кадры поворота (Frames + ChairView): `Frames.want_turntable(art)` ставит 36 WebP в очередь (с кадра текущего
ракурса в обе стороны) и выгружает прошлую коляску; декодирование `Image.load_webp_from_buffer` + mipmaps — в
`WorkerThreadPool` (до 3 кадров), без потоков — по ~6 мс за кадр игры; `ImageTexture` создаётся в главном потоке.
Пока кадров нет — рисунок коляски (`art_matched`). Рисование и кружки — прямой порт `_draw_turntable`,
`_m3d_frame`, `_m3d_spots`, `project_point`: кадр `index = round((yaw − yaw0)/(2π/n)) mod n`, масштаб
`fr.h/1250·zoom`, кадр в `(ax + off·scale, ay + off·scale)` размером `px·scale/ref`, тень — четырёхугольник под
колёсами в 1/10 разрешения, растянутый (размытие). Центры деталей — `centers` + `PART_CENTER_FIX` (из game.py в
game_consts.json); ближняя к низу экрана точка детали, скопления — веером, раздвигание, выноска к детали —
попиксельно совпадает с pygame (сверено на flat и joystick). Петли героев — `Frames.loop_frame(name, t)`:
показываются, когда все кадры в памяти (до того — статичная картинка), не показанные 30 с выгружаются.
Автозагрузки (синглтоны):
- `Content` — задания/варианты/Гильдия/посадка/инструменты/детали из JSON; проверка целостности при старте.
- `Loc` — `Loc.t("русская строка")` → строка на текущем языке (как `tr()` в игре); язык RU/EN.
- `Settings` — громкости, язык, размер текста, «Без анимации», шрифт, одна кнопка, качество; `user://settings.json`.
- `SaveGame` — прогресс в формате `save.json`; резервная копия; коды прогресса/заданий (позже).
- `Audio` — звуки по имени (`Audio.sfx("ok")`), музыка сцен с плавной сменой.
- `Frames` — кадры поворота и петли: загрузка WebP в фоне, кэш, выгрузка.
- `Nav` — смена экранов с переходом, стек «назад», параметры запуска (`?jobs=…` в браузере — позже).
- `Speech` — озвучка для незрячих (встроенная поддержка Godot + свои объявления).
- `Web` — браузерная сборка: параметры адреса (`?fps=1`, `?test=1`, `?prof=1`), сеть (`wnbNet` страницы), музыка
  (`wnbMusic`), плашка кадров/с, `window.wnbState` для web_smoke, пауза под заслонкой «поверни телефон» (`wnbOnCover`),
  язык игры — странице (`wnbLang`). На компьютере — только плашка по `-- --fps` и профиль по `-- --prof`.
- `Prof` (`ui/prof.gd`, не автозагрузка) — профилировка кадра по `?prof=1`/`--prof`, см. «Скорость на слабом процессоре».

## Риски
- **Озвучка в браузере.** Встроенная поддержка чтения с экрана в Godot работает на компьютере; в браузерном экспорте
  холст для неё «чёрный ящик». Возможно, придётся дублировать объявления в скрытую область страницы, как сейчас.
- **Слабый процессор** (браузер, ×6): было — мастерская 26, задание 17–21 к/с (телефон владельца — 27); причина
  найдена профилем (19.11): шейпинг текста каждый кадр и перерисовка неподвижного. Сейчас 55–60. Новые экраны и окна
  рисовать по тем же правилам (UI.draw_* с кэшем, перерисовка по изменению — GameButton.redraw_sig).
- **Память на телефоне.** Кадры без сжатия в видеопамяти: 36 кадров коляски ≈ 50 МБ. Держать только текущую коляску
  и текущую петлю, грузить заранее по одному кадру.
- **Размер браузерной сборки.** Движок ≈ 10 МБ в сжатом виде до первого кадра игры; всё тяжёлое — вне основного пакета.
- **Объём.** Кабинет посадки и доступность — самые дорогие части; оценка всего переноса — недели работы срезами.

## Отличия от релиза сейчас (сверка по снимкам tests/ref ↔ tests/shots, средняя разница 2,5–5,5 из 255)

- Нет 3D-осмотра (V; заменит настоящее 3D), озвучки F2.

## Экспорт в браузер (сделан 19.11, шаг 5)
Сборка: `python godot/tools/build_web.py [--base-url https://…/godot/] [--sync] [--serve [порт]]` → `godot/build/web/`
(не в git). Выкладывать папку целиком в любую подпапку сайта: все пути в index.html относительные. Проверка —
`python godot/tools/web_smoke.py` (сам собирает; `--no-build` — готовую; `--only boot,play,…`; `WNB_URL=…` — сайт).
- **Пресет** `export_presets.cfg` «Web»: однопоточный (`variant/thread_support=false` — GitHub Pages не отдаёт
  COOP/COEP), Compatibility (project.godot), холст на всё окно (`html/canvas_resize_policy=2`; игра — 16:9 с полями,
  stretch canvas_items/keep), своя страница `web/shell.html`. Экспорт прямо из редактора даст тяжёлый пакет без
  музыки — только через build_web.py.
- **Копия проекта** `build/web_stage/` (там же живёт её `.godot/` — импорт только изменившегося): код, сцены, i18n,
  web/, `content/data` (в `game_consts.json` — `share.base_url` из `--base-url` и блок `web`: метки версий кадров и
  музыки), шрифты, звуки, картинки (≥150 КБ — WebP с потерями 0,8, фоны — без mipmaps: рисуются 1:1), индексы
  `content/frames/*.json`. Кадров и музыки в пакете нет.
- **Рядом с игрой:** `frames/turntable/*.webp`, `frames/anim/<петля>/*.webp` (все кадры — и поворот, и петли
  проезда/волшебства/машущих, и Бренна), `music/<тема>.mp3` (моно, ffmpeg q5), `splash.jpg` (заставка загрузки).
- **Метка версии:** файлы движка и пакета — по хэшу (`wnb-engine-<хэш>.wasm/.js/…`, `wnb-<хэш>.pck`, GODOT_CONFIG
  правится); кадры и музыка — `?v=<хэш>` (игра берёт из `game_consts.json` → `web`).
- **Кадры по сети** (`Frames.net`): fetch страницы (`wnbNet`, до 6 одновременно, кэш браузера), WebP распаковывает
  Worker страницы (createImageBitmap → WebGL2 → readPixels, байты = PIL), игра забирает RGBA через
  `JavaScriptBridge.eval` и строит текстуры (≤5 мс за кадр игры, не меньше одного кадра). Почему не HTTPRequest:
  узел на каждую загрузку, абсолютные адреса, тело читается порциями в игровом кадре, а распаковка всё равно была бы
  в игровом потоке; fetch идёт параллельно и мимо игры, а Worker распаковывает в другом потоке и в однопоточной
  сборке. Нет Worker/OffscreenCanvas/WebGL2 (`?decode=godot` — принудительно) — игра распаковывает сама.
  Пока кадров нет — запасной вид: коляска рисунком, проезд скользящим портретом, «волшебства» нет, машущие — картинкой;
  404/обрыв — один повтор, потом запасной вид до конца сеанса (как AnimWeb). Петля героя качается с начала задания
  (после кадров поворота), петля Гильдии — пока читают перед «Проверкой под нагрузкой».
- **Музыка** — `<audio>` страницы (`wnbMusic`): старт по первому нажатию/клавише, пауза в фоновой вкладке, громкость
  и переходы тем — из Audio (как на компьютере). Эффекты и фоновые петли — режим Sample.
- **Сохранения** `user://` → IndexedDB (Godot сбрасывает запись сам после закрытия файла; перезагрузка через 0,4 с
  после смены настройки — на месте). **Перенос из pygame-версии:** если своего save.json нет, а в localStorage того же
  сайта есть `wnb:save.json` (и `wnb:settings.json`, `wnb:save.bak.json`) — берутся один раз (формат тот же), старое не
  трогается (`SaveGame.migrate_web`, `Settings.web_legacy`).
- **Страница:** заставка с полосой загрузки (МБ), гаснет с первым кадром игры; поле ввода кода — настоящее `<input>`
  поверх рамки (на телефоне — экранная клавиатура по касанию, на компьютере — фокус сразу; Enter — «Применить», Esc —
  закрыть); скрытая `#wnb-live` (aria-live) и голос браузера по F2 (`wnbSay`); `?fps=1` — плашка и
  `[wnb] fps …` в консоль раз в 3 с; `?test=1` — `window.wnbState` (для web_smoke).
- Полный экран — кнопка «ВКЛ / ВЫКЛ (F11)» в настройках → ГРАФИКА (работает: Godot зовёт обработчик внутри события).
- **Телефон и планшет** (19.11, как `web_setup_touch` в game.py; всё — в `web/shell.html`, игра только встаёт на паузу):
  телефон (меньшая сторона экрана < 700 CSS px) в книжной ориентации (`screen.height > screen.width` и окно выше
  0,9 ширины) — заслонка «↻ Поверни телефон боком, чтобы играть»; планшет — пока окно выше, чем шире, с кнопкой
  «Играть так (книжная ориентация)» (до перезагрузки). Заслонка — с первого кадра страницы, поверх заставки загрузки;
  касания по ней до холста не доходят. Пока она видна, страница зовёт `wnbOnCover(true)` → `Web`: дерево на паузе и
  `RenderingServer.render_loop_enabled = false` (кадры не рисуются, холст 1080×1977 зря не греет телефон).
  Первое касание на телефоне — полный экран и `screen.orientation.lock('landscape')`; кнопка ⛶/✖ 44×44 у левого края
  по центру; на компьютере — «✖ Выйти из полного экрана (Esc)» внизу при полном экране или F11 (во фрейме сайта — только
  при полном экране документа). Тексты — на языке игры: до загрузки — последний язык игры (`localStorage
  wnb-godot:lang`) или язык браузера (ru → русский, иначе английский), потом игра сообщает свой (`wnbLang`). Заставка
  загрузки — тоже на этом языке.
- **Плашка `?fps=1`** на сенсорном экране — шрифт 24 (а не 13) и две строки; вторая: холст в px, окно в CSS-пикселях,
  devicePixelRatio (и «→ эффективный (res N)», если сработал потолок), кадры. Плюс строка страницы у верхнего края
  (HTML, 11 px): `inner · vv · screen · canvas css · buf · godot · fs · ориентация` — видна, даже если холст уехал.
- **Потолок разрешения холста `?res=N`** — высота игровой картинки 16:9 в пикселях холста; страница считает буфер
  холста как CSS-размер × эффективный dpr (политика холста 0, см. «Грабли браузерного экспорта»; `devicePixelRatio`
  подменён тем же числом), CSS-размер тот же, браузер растягивает. По
  умолчанию 1080 и не ниже 1: на телефоне 360 CSS px × dpr 3 = 1080 — без изменений; планшеты и экраны с большой
  плотностью (картинка выше 1080 px) — до 1080: арт игры 1280×720 (фоны — 1:1), выше 1,5× логического размера
  выигрыша нет, а пикселей для видеокарты в 1,5–3 раза больше. `?res=720` — в 2,25 раза меньше пикселей (для замера на
  телефоне); `?res=0` — без потолка. В Chromium с замедлением процессора разницы нет (×6, телефон: мастерская 60 и с
  ?res=720) — замедление CDP касается только процессора, видеокарту телефона так не проверить: сравнивать на телефоне.

### Грабли браузерного экспорта (19.11, шаг 5)
- Папки с `.gdignore` в экспорт не попадают даже с фильтром «включить» (`content/frames/*.json` не было в пакете) —
  поэтому сборка идёт из копии проекта `build/web_stage/`, где у `content/frames/` остались только индексы *.json.
- Всё, что лежит внутри копии проекта, Godot импортирует и кладёт в пакет: кеш перекодированной музыки в
  `web_stage/music_cache` дал +3,7 МБ к .pck — кеш вынесен в `build/web_music_cache/`.
- Копия проекта внутри `godot/` видна основному проекту: редактор импортировал бы её, самопроверка нашла бы «двойные»
  class_name («Class "BgLayer" hides a global script class») — в `build/` лежит `.gdignore`, самопроверка пропускает
  `build/` и папки с `.gdignore`.
- Первый `--headless --import` свежей копии (пустая `.godot/`) у 4.7.2 иногда падает (код 0xC0000005, на шрифте
  Atkinson); второй доимпортирует остальное — build_web.py повторяет импорт сам.
- Имена файлов движка и пакета: загрузчик строит адреса из `GODOT_CONFIG.executable` (`<имя>.wasm`, `.js`,
  `.audio.worklet.js`, `.audio.position.worklet.js`) и `mainPack`; метку версии против кеша делаем переименованием
  (`wnb-engine-<хэш>.*`, `wnb-<хэш>.pck`) и правкой `executable`/`mainPack`/`fileSizes` — «?v=» к .wasm приписать нельзя.
- **Касание = два нажатия.** С `emulate_mouse_from_touch` кнопка получает и само касание (InputEventScreenTouch), и
  мышь из него; у GameButton `ACTION_MODE_BUTTON_PRESS` — «начать» открывал мастерскую, и то же касание сразу жало
  карточку под пальцем (на телефоне — задание «lift» вместо мастерской). Nav._input не отдаёт касания интерфейсу
  (мышь из них приходит и так). Ползунки посадки работают на мыши из касания.
- Режим звука Sample (по умолчанию в браузере с 4.3) перед первым воспроизведением распаковывает поток в память
  целиком — музыкальная тема 3–4 мин это десятки МБ и заметная пауза. Музыку играет `<audio>` страницы (Audio →
  Web.music_*), эффекты и фоновые петли — Sample (без треска в однопоточной сборке, Stream там трещит).
- Распаковка WebP в WebAssembly — 3,6 мс на кадр поворота на быстром ПК (в 2 раза медленнее родной), ×6 замедления —
  30 мс: пока качаются кадры, кадр игры заметно тяжелеет. Распаковку делает Worker страницы (createImageBitmap →
  WebGL2 → readPixels), игре — 0,4 мс (копия пикселей + mipmaps). Чтение через 2D-холст (getImageData) НЕ годится:
  холст хранит цвет домноженным на прозрачность — под прозрачными пикселями цвет пропадает (тёмная кайма у краёв);
  WebGL2 с `UNPACK_PREMULTIPLY_ALPHA_WEBGL=false` даёт байты один в один с PIL (проверка в web_smoke).
- **Сглаженные круги и ломаные — по 2–3 вызова рисования каждая** (Compatibility/GLES3, сверено по исходникам 4.7:
  `servers/rendering/renderer_canvas_cull.cpp`, `drivers/gles3/rasterizer_canvas_gles3.cpp`). `draw_line(…, true)` —
  9 «примитивов» по 4 точки (сердцевина, 4 кромки, 4 угла), примитивы с одинаковым числом точек и текстурой движок
  склеивает в один вызов. А `draw_circle(…, true)` — 2 многоугольника (веер 64 сегмента + кромка), `draw_polyline` /
  `draw_arc` с antialiased — 3 (полоса + 2 кромки), `draw_colored_polygon` — 1, и каждый многоугольник — свой вызов
  и рвёт пачку линий вокруг. В браузере вызов ≈ 25–30 мкс процессора при ×6: скелет с кругами — 300–800 вызовов,
  10–20 мс. Лечится одной пачкой: `RenderingServer.canvas_item_add_triangle_array(ci, PackedInt32Array(), точки,
  цвета)` — без индексов рисует точки подряд тройками, цвет по вершинам, порядок треугольников = порядок перекрытия.
  Геометрию сглаживания можно повторить точно (кромка `FEATHER_SIZE` 1,25 до прозрачного, толщина линии
  уменьшается `canvas_item_get_compensated_antialiasing_width`, радиус круга — на 0,3125) — снимки «Без анимации» до
  и после отличаются не больше чем на 10 из 255 на кромках (`SeatFigure`, 20.11).
- `Transform2D(0.0, сдвиг) * PackedVector2Array` — сдвиг всего массива одним вызовом (готовый круг вокруг (0, 0) →
  на место); поэлементные циклы в GDScript в браузере при ×6 — ~0,5 мкс на действие, сотни фигур в кадр не тянут.
- `UI.wsin` (sin с проверкой «Без анимации») — 0,3 мкс против 0,06 у `sin`: в цикле по точкам каждый кадр — заметно.
- `JavaScriptBridge.eval` возвращает `Uint8Array`/`ArrayBuffer` как PackedByteArray — так байты кадров идут в игру.
- `push_warning`/`push_error` в браузере — `console.error`; 404 на сотню кадров давал сотню строк — теперь одно
  предупреждение на набор.
- Полный экран в браузере работает из кнопки настроек: Godot вызывает обработчик кнопки внутри события страницы.
- **Текст каждый кадр — дорого.** У `Font` кэш раскладки строк на 64 записи (LRU): экран, который каждый кадр рисует
  и меряет больше строк, шейпит всё заново (на телефоне — десятки мс за кадр). Свой кэш — `UI.px_width/text_line`.
  `TextLine.draw(rid, базовая_линия − (0, get_line_ascent()))` даёт те же пиксели, что `draw_string` (при целых
  координатах; при дробных — сверять снимки).
- Неподвижное не перерисовывать: `queue_redraw()` каждый кадр «на всякий случай» стоил больше, чем вся логика игры.
  Анимированную часть — в отдельный дочерний слой (`show_behind_parent = true` — нарисовать под родителем).
- Новый `class_name` (ui/prof.gd) не виден самопроверке `-s …` до `--headless --import` (кэш глобальных классов в
  `.godot/`): «Identifier "Prof" not declared», и самопроверка висит.
- Пауза под заслонкой: `get_tree().paused` + `RenderingServer.render_loop_enabled = false`; JS зовёт игру через
  `JavaScriptBridge.create_callback` (ссылку на колбэк держать в переменной узла).
- **Размер холста ведёт страница (политика холста 0), а не движок по innerWidth/innerHeight.** При
  `html/canvas_resize_policy=2` движок каждый кадр (`GodotDisplayScreen.updateSize`) брал окно =
  `window.innerWidth/innerHeight × devicePixelRatio` и сам писал холсту `style.width/height`. На телефоне владельца
  (Huawei Mate 20 Pro, Chrome, 780×360 CSS, dpr 3) после полного экрана и `orientation.lock('landscape')` из книжной
  `innerHeight` оставался 780: окно Godot 780×780, картинка 16:9 (780×439) с полями сверху 170 px — шапка внизу
  чёрной полосы, низ игры за экраном. В эмуляции Playwright не видно (там innerHeight честный). Теперь пресет — политика
  0: движок только сверяет `canvas.width/height` с прошлым размером и, если изменились, берёт их как окно
  (`desired_size`, `_updateGL`), CSS не трогает; касания и мышь считаются по `getBoundingClientRect()` и
  `canvas.width/rect.width` — от политики не зависят. Страница (`wnbView` в shell.html): видимый размер — по раскладке
  CSS (невидимый `#wnb-vp` `position: fixed; inset: 0`), не больше `visualViewport` (кроме набора в поле — экранная
  клавиатура) и на сенсорном экране не больше `screen.width/height` (короткая/длинная сторона по
  `screen.orientation.type` — так и на iPhone, где screen не поворачивается); целые CSS px, буфер = CSS × effDpr
  (потолок `?res=`). Холст `position: fixed` в левом верхнем углу, документ не раздвигает; в `<meta viewport>`
  `minimum-scale=1, maximum-scale=1`. Пересчёт: resize, visualViewport resize, ResizeObserver мерки, раз в 0,5 с; после
  orientationchange / `screen.orientation` change / fullscreenchange / снятия заслонки / удачного `lock` — ещё 8 раз за
  1,5 с (размеры на Android приходят с опозданием и по одному). Поле кода переставляется за холстом
  (`wnbField.relayout`). `window.devicePixelRatio` подменён тем же effDpr (Godot `screen_get_scale`).
  Проверка — web_smoke `stale`: окно 780×360, `innerHeight` подменён на 780 после «поворота» из книжной (и `innerWidth`
  = 360 с загрузки): до правки картинка была в 0,171 780×439 (как на снимке владельца), после — 70,0 640×360.
  `?fps=1` — строка `inner · vv · screen · canvas css/buf · godot · fs · ориентация` у верхнего края страницы
  (HTML, поверх холста): по снимку видно, какое из значений врёт.
- Playwright: `page.screenshot()` возвращает свой размер окна и сбрасывает `Emulation.setDeviceMetricsOverride` —
  «поворот телефона» в web_smoke делается `set_viewport_size` + CDP (screen и orientation); окно в полном экране
  (после первого касания на телефоне) Playwright не ресайзит — сначала `document.exitFullscreen()`.
- Проверка в Playwright: по умолчанию headless-Chromium рисует WebGL программно (SwiftShader) — для честных кадров/с
  `--use-angle=d3d11 --enable-gpu --ignore-gpu-blocklist`. Playwright помечает страницу «уже нажатой»
  (`userActivation.hasBeenActive`), поэтому запрет автозапуска звука до первого нажатия проверкой не виден.
  speechSynthesis на Windows говорит через SAPI мимо `--mute-audio` — в проверке он подменён заглушкой.
