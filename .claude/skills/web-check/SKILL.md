# Проверка браузерной версии

Браузерная версия — **главная** (сайт игроков). selftest, keyboard/switch/pad/ui_playthrough гоняют
настольную версию и браузерные ошибки не видят. Поэтому после правок — цикл
**правка → настольные проверки → web_smoke → открыть скриншоты → исправить → снова**.
Идея цикла — из скилла develop-web-game (OpenAI, Apache 2.0), переделана под Python/pygbag.

## Порядок

1. Настольные проверки (AGENTS.md → «Проверки»): `python game.py --selftest`, `py game.py --selftest`,
   `python art_tests/keyboard_playthrough.py [en]`, `python art_tests/ui_playthrough.py`,
   `python art_tests/audit2/check_en_coverage.py` (+ switch_playthrough / pad_playthrough, если трогали ввод).
2. `python art_tests/web_smoke.py` — собирает (build_web.py --serve, ~1–2 мин), открывает Chromium (Playwright)
   и проходит сценарии: окно как на сайте 1100×620, весь экран 1920×1080, ноутбук 1366×768 @125 %,
   телефон горизонтально (касания, поворот коляски пальцем, поле отзыва с экранной клавиатурой, «Отмена»),
   телефон вертикально (просьба повернуть), поддельный геймпад (Start, B, крестовина + A).
   Сверяет состояние игры `window.wnbState` (= `Game.debug_state()`: сцена, задание, окна, размер кадра,
   какие картинки не загрузились) и ошибки Python/JS в консоли. Код выхода 1 — есть FAIL.
   `--no-build` — если сервер `build_web.py --serve` уже запущен.
3. **Открыть и посмотреть скриншоты** `art_tests/web_shots/*.png` (Read) — то, что на них, и есть правда:
   обрезанный текст, заглушки вместо арта, налезания тесты не ловят.
4. Новая возможность → добавить её сценарий в web_smoke.py (и проверку состояния — поле в debug_state).
5. Только потом коммит, `python build_web.py --deploy`, дождаться GitHub Pages
   (`gh api repos/fordragon88/wheels-and-bones-web/pages/builds/latest --jq .status` = built).

## Что уже известно про pygbag (не наступать снова)

- **WebP не читается** — картинки только PNG/JPEG (крупные рисунки: JPEG + `<имя>.a.png` прозрачность, build_web.py).
- **numpy нет** — 3D в браузере только кадрами поворота (assets/turntable).
- Картинку из памяти pygame не грузит — через временный файл.
- **Касание приходит дважды**: SDL шлёт MOUSEBUTTONDOWN *до* FINGERDOWN в той же пачке — `finger_events()` отбрасывает эхо.
- **RS в браузере дробный (0,6–2)**: кадр ровно под окно (`web_target_res`). Любой `set_clip` — только
  `_rr(rect, _rs(surf))`; логические прямоугольники в сырые вызовы pygame не передавать.
- Простой `http.server` не отдаёт `/cdn` pygbag — только `build_web.py --serve`.
- В тестах никогда не жать «Отправить» в окне замечания; web_smoke блокирует script.google.com.
- **Память**: кадры поворота держит только коляска на экране (`Turntable.release`); всё, что кэшируется в браузере,
  ограничивать — на телефоне кончается память и игра «зависает».
- **Не трогать фокус холста** при смене размера (c.focus() после set_mode вешал вкладку — бесконечный цикл).
- Ошибки Python в браузере — не в консоли, а в терминале pygbag на странице (`.xterm-rows`).
- Встроенная панель браузера Claude, когда скрыта, «замораживает» страницу — для проверок Playwright (headless).
