# Ссылки и коды: перенос прогресса, задания для учеников, итог

Всё описанное включается **только** по ссылке с параметрами или кнопками в «Настройки → ИГРА».
Обычный игрок без них идёт прежним путём; `save.json` остаётся прежнего формата (ключ `"assign"` появляется
только у того, кто открывал ссылку-задание; старые версии игры его просто не читают).

Код в `game.py`: блок «Ссылки и коды» (после `feedback_flush_outbox`) — чистые функции `share_encode`/`share_decode`,
`progress_pack`/`progress_unpack`, `assign_parse`, `assign_code`, `share_link`, `parse_link`, `result_pack`/`result_unpack`,
`result_text`, буфер обмена `clipboard_put`/`clipboard_get`, JS `web_setup_share`; в `class Game` — раздел
«ссылки и коды» (`apply_link`, `apply_code`, `start_assignment`, `exit_assignment`, `assign_record`, `apply_progress`,
`restore_backup`, окно `share_ui`: `open_share`, `_draw_share`, `handle_share_event`, `_share_action`).
Проверки — в `python game.py --selftest` (раздел «ссылки и коды») и `art_tests/web_smoke.py` (сценарий `links`).

## 1. Ссылки

База — страница сайта `SHARE_BASE_URL = https://www.openassistivetech.org/wheels-and-bones/` (игра там в `<iframe>`;
скрипт из `wordpress_embed.html` пробрасывает параметры `load/jobs/seat/from/title` в адрес iframe). Те же параметры
работают и напрямую: `https://fordragon88.github.io/wheels-and-bones-web/?jobs=…`.

| Параметр | Значение | Пример |
|---|---|---|
| `load` | код прогресса (см. ниже) — игра спросит «Загрузить прогресс из ссылки? Текущий прогресс будет заменён» | `?load=P.eNo9jD0K….a1b2c3` |
| `jobs` | id поломок через запятую, в нужном порядке | `?jobs=flat,caster,brake` |
| `seat` | id примерок Кабинета посадки через запятую | `&seat=seat_troll,seat_elf` |
| `from` | имя того, кто дал задание (необязательно, до 40 знаков) | `&from=%D0%90%D0%BD%D0%BD%D0%B0` (Анна) |
| `title` | заголовок задания (необязательно, до 80 знаков) | `&title=Unit%201` |

Неизвестные id и повторы отбрасываются; если не осталось ни одного известного id — ссылка игнорируется.
Параметры, которых нет в списке, игра не читает. Имя и заголовок кодируются как обычно в адресе (`%D0%…`, пробел — `%20`).

Пример: `https://www.openassistivetech.org/wheels-and-bones/?jobs=flat,caster&seat=seat_elf&from=Anna&title=Week%201`

### Режим задания
- Номер задания (`id`) — crc32 от `jobs, seat, from, title` (8 hex, `assign_id`). Та же ссылка (тот же id) после
  перезагрузки страницы продолжает задание с места; ссылка с другим id начинает новое.
- Вверху мастерской — плашка «Задание от <Имя>: 0/3»; в очереди только назначенные поломки по порядку; в Кабинете
  посадки — только назначенные примерки. Обучение, замки «откроется после N ремонтов», Гильдия, гараж и вечеринка не
  показываются (кнопок нет), всё назначенное доступно сразу; с титула — сразу в мастерскую (без вступления).
- Прогресс задания — в `save.json` → `"assign"`: `{"id", "jobs", "seat", "from", "title", "done", "errors", "secs",
  "active", "sent"}`. Обычные `done/garage/seat_done/seat_quiz_ok` в режиме задания **не меняются**.
- В итог идёт **первая** попытка каждого пункта (переигрывание её не меняет). Ошибки поломки — как на экране итога
  (`mistakes`), примерки — число нажатий «Проверить» с неверной посадкой; время — от начала пункта до «ГОТОВО».
- «Выйти из задания» (кнопка в мастерской и в окне итога) — обычная игра с обычным прогрессом. Прогресс задания
  остаётся в `save.json` (`"active": false`): та же ссылка вернёт его с места.
- Всё выполнено — окно «Итог задания»: список пунктов (✔, ошибки, время), общая строка «3/3, ошибок 2», кнопки
  «Скопировать код результата», «Скопировать текстом», «Отправить в таблицу» (только если задан `FEEDBACK_URL`),
  «Выйти из задания», «В мастерскую». Потом итог открывается кнопкой «ИТОГ ЗАДАНИЯ» в мастерской.

## 2. Коды

Общий вид: `<вид>.<тело>.<crc>`

- вид: `P` — прогресс, `J` — задание, `R` — результат;
- тело: base64url (без `=`) от `zlib.compress(JSON)` (JSON — компактный, ключи по алфавиту);
- crc: 6 hex = `crc32(соль + вид + "." + тело + соль) & 0xFFFFFF`; соль пустая у `P`/`J`, у `R` — `RESULT_SALT`.

Пробелы и переносы строк при вставке игнорируются (код на экране показывается группами по 6 знаков — чтобы переписать
руками). Битый код, чужая контрольная сумма, неизвестный вид или `"v" ≠ 1` → «Код не распознан», прогресс не трогается.
Длина: прогресс ~130–250 знаков, задание ~140, результат ~150–300.

| Вид | JSON |
|---|---|
| `P` | `{"v":1, "d":[done…], "g":[[id, звёзды]…], "e":exam_passed, "s":[seat_done…], "q":seat_quiz_ok, "t":tutorial_skipped}` |
| `J` | `{"v":1, "j":[jobs…], "s":[seat…], "f":"from", "ti":"title"}` |
| `R` | `{"v":1, "a":"id задания", "f":"from", "ti":"title", "it":[все пункты по порядку], "r":[[пункт, ошибок, секунд]…] (только выполненные), "gv":"версия игры"}` |

**Соль результата** — защита от наивной правки цифр руками (поправили тело — сумма не сойдётся; пересчитали crc32
без соли — тоже). Это не шифр: соль лежит в открытом коде игры, знающий человек подделает код. Для оценок «по-честному»
используйте отправку в таблицу.

«Настройки → ИГРА → ВСТАВИТЬ КОД» принимает: код `P` (вопрос «Загрузить прогресс из кода?»), код `J` (вопрос «Начать
задание от …?»), код `R` (карточка результата, только чтение), а также ссылку целиком с `?load=` или `?jobs=`.

## 3. Кнопки в «Настройки → ИГРА»

- **СКОПИРОВАТЬ КОД** — код `P` текущего прогресса (в браузере — `navigator.clipboard.writeText`, запасной путь —
  `document.execCommand('copy')`; на десктопе — SDL `SDL_SetClipboardText` (через ctypes из пакета pygame; у pygame-ce —
  `pygame.scrap.put_text`), запасной путь — tkinter). Окно показывает код в поле (в браузере его можно выделить и
  скопировать вручную); если буфер недоступен — код крупно, группами, «перепиши или сфотографируй».
- **ВСТАВИТЬ КОД** — поле ввода (браузер: настоящее поле страницы поверх холста — вставка Ctrl+V, экранная клавиатура;
  десктоп: Ctrl+V или кнопка «ИЗ БУФЕРА»).
- **ССЫЛКА-ЗАДАНИЕ** — конструктор: отметки по 21 поломке (названия как в очереди: клиент и поломка) и 9 примеркам,
  порядок — порядок отметок (цифры 1, 2, 3…), поле «От кого». В браузере — «Скопировать ссылку», на десктопе (exe) —
  «Показать код задания» (код `J`, ученик вставит его через «Вставить код»).
- **ССЫЛКА С ПРОГРЕССОМ** (только браузер) — `SHARE_BASE_URL + "?load=" + код`.
- **ВЕРНУТЬ ПРЕЖНИЙ ПРОГРЕСС** — видна, пока есть копия: перед любой заменой прогресса кодом/ссылкой старый прогресс
  пишется в `save.bak.json` (+ `localStorage["wnb:save.bak.json"]` в браузере). После возврата копия удаляется.
- В браузере ответ на вопрос «загрузить прогресс из ссылки?» запоминается (`localStorage["wnb:load_seen"]` = crc кода),
  чтобы перезагрузка страницы с той же ссылкой не спрашивала снова.

## 5. Отправка итога в таблицу

Кнопка «ОТПРАВИТЬ В ТАБЛИЦУ» идёт тем же каналом, что замечания (`feedback_send`: на десктопе — очередь
`feedback_outbox.json` и досылка при следующем запуске, в браузере — `wnbSend` с очередью `wnb:outbox`). Отправляется
один раз на задание (`"sent": true`). Поля — **те же, что у замечания**, поэтому нынешний `docs/feedback/Code.gs`
(лист «Feedback») запишет строку без изменений: Screen=`assignment`, Job=id задания, Title=заголовок, Type=`result`,
Reason=`From: <имя>`, Player chose=`3/3, mistakes 2`, Comment=итог текстом по-английски (с кодом результата).
Сверх них в JSON есть `type: "result"`, `assignment`, `from`, `jobs: {id: {done, errors, secs}}` — нынешний скрипт их
просто не читает (берёт поля по именам), `FEEDBACK_URL` не менялся.

Если хочется отдельный лист «Results» с колонками по заданиям — владелец вставляет в Apps Script (в `doPost`, сразу после
проверки `d.key !== KEY` и лимита) этот фрагмент и заново развёртывает веб-приложение (адрес `/exec` при «Управлять
развёртываниями → Изменить → Новая версия» не меняется):

```javascript
    if (d.type === "result") {                       // итог задания по ссылке (Wheels & Bones, docs/SHARE_LINKS.md)
      const ss = SpreadsheetApp.getActiveSpreadsheet();
      const sh = ss.getSheetByName("Results") || ss.insertSheet("Results");
      const H = ["Received", "Player time", "Version", "Platform", "Language", "Assignment", "From", "Title",
                 "Score", "Tasks (id: mistakes, m:ss)", "Text"];
      if (sh.getLastRow() === 0) { sh.appendRow(H); sh.setFrozenRows(1); }
      const jobs = d.jobs || {};
      const fmt = s => Math.floor((s || 0) / 60) + ":" + ("0" + ((s || 0) % 60)).slice(-2);
      const tasks = Object.keys(jobs).map(k => k + ": " + (jobs[k].done ? jobs[k].errors + ", " + fmt(jobs[k].secs)
                                                                         : "not done")).join("; ");
      sh.appendRow([new Date(), cell_(d.time), cell_(d.version), cell_(d.platform), cell_(d.lang),
                    cell_(d.assignment), cell_(d.from), cell_(d.title), cell_(d.got), cell_(tasks, 2000),
                    cell_(d.comment, 2000)]);
      return reply_(true, "");
    }
```

Без этого фрагмента итоги ложатся строками в лист «Feedback» (как замечания, Type = `result`).

## 6. Как откатить

- Всё — в коммитах ветки `feature/share-links`; откат — `git revert` этих коммитов (или не сливать ветку).
- Только убрать кнопки, оставив разбор ссылок: в `_share_set_rects` вернуть пустой список.
- Отключить ссылки: в `main()` убрать строку `game.apply_link(web_link_query())` — `?jobs=`/`?load=` перестанут читаться.
- У игрока: «Выйти из задания» — обычная игра; «Вернуть прежний прогресс» — прогресс до загрузки кода. Ключ `"assign"`
  в `save.json` можно удалить вручную — игра его не требует.
- На сайте: вернуть прежний блок `wordpress_embed.html` (без скрипта проброса параметров) — ссылки на страницу сайта
  перестанут передавать параметры, прямые ссылки на github.io продолжат работать.
